한국어 안내 문구 기준 — 2026-10-18

적용 범위: lab.html의 미션, 기록·수정·검토 창, 실험, 단계 탐색, 오류 안내, 세 가지 2D 실습, 이슈·충돌 실습, 변화 애니메이션.
ASD-STE100의 주요 원칙을 한국어에 맞게 적용한다. 영어 통제 어휘·품사·단어 수 규칙의 정식 준수를 주장하지 않는다.

용어
- 나 / 지수: 행동 주체. 지수는 가상 인물이다. 역할명만으로 사람을 가리키지 않는다.
- 내 저장소 / 지수의 저장소 / GitHub 저장소: 기록이 있는 장소.
- 내 컴퓨터 / 지수의 컴퓨터: 작업이 일어나는 기기.
- 기준본: 각 저장소에서 main이 가리키는 상태. ‘원본’은 사용하지 않는다.
- 작업 공간: 별도 변경을 준비하는 브랜치. 행동 뒤에 브랜치 이름을 설명한다.
- 파일 저장 / 변경 기록: 서로 다른 행동. 기록은 커밋이다.
- 기록 공유 / 변경 합치기 / 기준본 받아오기: push / merge / pull.
- 검토 / 승인: review / approval. 검토와 승인을 하나의 행동으로 표현하지 않는다.

작성 규칙
1. 지시는 한 번에 한 행동만 제시한다. 결과 설명은 별도 문장으로 쓴다.
2. 버튼을 지시할 때는 실제 버튼 이름을 그대로 쓴다.
3. 기본 미션은 같은 label 값으로 버튼과 안내를 생성한다.
4. 본문과 재수정에는 한 가지 문장만 제시한다. “이 문장 저장하기” 동작 하나를 안내한다.
5. 지수는 모든 PR의 검토·승인·병합을 담당한다. 사용자의 행동과 지수의 행동을 구분한다.
6. 조건이 필요하면 조건을 먼저 쓴다. 예: 이전 단계에서 새 동작을 하면 이후 진행 결과는 다시 만듭니다.
7. ‘여기’, ‘팀 쪽’, ‘동료 표시’ 대신 대상과 위치를 명시한다.
8. 안내는 ‘누르세요/선택하세요’, 상태 설명은 ‘입니다/했습니다’로 쓴다. 지수와의 대화는 자연스러운 말투를 유지한다.
9. 실제로 없는 구슬·동화책·3D 조작을 안내하지 않는다.
10. 친숙한 이야기 본문 자체는 통제 언어로 바꾸지 않는다. 학습 대상은 협업 과정이다.

- 규칙 5.2: 동시에 일어나는 동작을 제외하면 문장마다 하나의 지시를 쓴다.
- 공식 FAQ: 짧은 문장, 한 문장에 한 주제, 능동 표현, 용어의 일관성을 다른 글에도 적용할 수 있다.

변화 설명은 본문에 유지한다. 다음 동작은 지도 애니메이션이 끝나면 실행할 수 있다. 재생 버튼은 같은 상태 변화를 다시 보여 주며 실습 상태를 변경하지 않는다.

변경 설명은 팝업으로 자동 표시하지 않는다. 본문 요약과 사용자가 펼치는 도식으로 제공한다. 최초 상태의 로컬 저장소와 .git은 존재하지 않으며, 복제 후에만 나타난다.
