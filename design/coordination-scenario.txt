이슈·브랜치·충돌 실습 — 2026-10-18

- 두 이슈를 나와 지수에게 한 개씩 할당하는 고정 시나리오. 할당은 책임 표시이며 브랜치 생성이나 파일 잠금이 아니다.
- 각 로컬의 main O에서 ending과 seven 브랜치를 만든다. 브랜치 생성만으로 새 커밋은 생기지 않는다.
- 같은 파일 같은 줄을 A/B로 각각 고친다. PR #31/#32는 모두 main을 대상으로 한다.
- 두 PR은 초기 main O 기준으로는 각각 병합 가능하다. 하나를 먼저 합쳐 main이 M1이 되면 남은 PR이 M1과 충돌한다.
- 해결은 GitHub 편집기에서 한다. 남은 PR 브랜치에 R을 기록하며, 부모는 해당 PR head와 M1이다. main은 아직 M1이다.
- 해결한 기록은 재검토한다. 승인 후 M2로 병합한다. 각 컴퓨터는 별도로 M2를 받아온다.
- 어느 PR을 먼저 합쳐도 동작하며, 세 가지 해결 문장과 이전 단계 복원을 지원한다.
- 여러 PR 자체가 충돌 원인은 아니다. 내용이 겹치는 경쟁 변경을 합칠 때 사람이 결정해야 하는 경우를 보여 준다.
