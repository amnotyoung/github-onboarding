직접 사용하며 발견하고 수정한 사항
- 320px에서 C/D와 D/M1 기록 버튼의 터치 영역이 겹쳤다. 기록 버튼을 44×44px로 분리하고 간격을 조정했다.
- 긴 변경 카드가 확인 버튼에 자동 포커스되며 아래로 스크롤됐다. 제목에 포커스를 두고 본문과 확인 버튼 영역을 분리했다.
- 이전 단계로 이동한 뒤 재생하면 현재 설명 대신 ‘단계 탐색’을 재생했다. 선택한 상태의 이전 스냅숏에서 실제 변화를 다시 구성한다.
- 카드 종료 후 포커스가 닫힌 확인 버튼에 남았다. 탐색은 단계 선택 상자, 재생은 재생 버튼, 작업은 다음 작업 구역으로 돌린다.
- 완료 화면이 재시작을 지시했다. 완료 결과와 배운 내용을 보여 주고 재시작은 선택으로 남겼다.
- 브랜치가 B를 복사하는 것처럼 보였다. 하나의 B를 main과 새 브랜치 두 이름이 가리키도록 변경했다.
- 기록·병합 도식의 출발점에도 결과 ID를 표시했다. 파일 → C, B + D → M1처럼 실제 입력과 결과를 구분했다.
- 완료된 첫 PR이 현재 main M2를 가리켰다. 그 PR이 만든 병합 기록 M1을 표시한다.
- 작은 화면에서 첫 복제 버튼이 아래로 밀렸다. 상단을 줄이고 빈 저장소의 복제 버튼을 먼저 배치했다. 390×844에서 버튼 하단은 775.75px이다.
- 본문 일부를 보여 주는 곳에는 ‘snow-white.md · 3번째 줄’을 표시했다.

요구사항별 완료 근거
1. 세 탭 / 3D 제거
   lab.html의 세 tab, workshop-model.mjs의 세 모드, 브라우저 탭 이름 및 canvas·Three.js 요청 부재 확인.
2. 복제 전 로컬 부재
   모든 모드의 초기 repos.mine/jisu=null. 모델 테스트와 실제 초기 화면에서 폴더·파일·기록 0개 확인. 각자 복제 후에만 생김.
3. 수정 문장과 지수 의견 반영 각 한 가지
   fileEdit의 고정된 after 문장. 모든 수정 창에서 after 영역 1개, 라디오·선택 상자 0개 확인.
4. 지수의 단독 검토·승인·병합
   PR 작성자=나, reviewer/approval.by/mergedBy=지수. 모델과 세 경로의 실제 PR 상태·동작 문구를 대조.
5. 변경 카드 지속과 애니메이션
   일반 모션에서 3.2초, 해결 카드에서 2.2초 후에도 유지. 모션 감소에서도 유지. 확인/ESC만 닫고 다음 작업 자체를 실행하지 않음.
6. 시각적 이슈·충돌 처리
   담당자 배지가 이슈에 연결됨. 공통 시작/현재 기준본/PR의 같은 줄을 비교하고 두 내용의 색상을 보존한 결과를 표시. 편집 후 R 기록 전까지 병합 불가.
7. 통합 실습의 연속성
   같은 GitHub 저장소에 C/D/H/M1/R/M2가 남음. 재검토, 병합, 각자 받아오기까지 한 경로로 완료. 탭 변경은 각 경로 상태 보존.
8. 탐색과 재생
   이전 단계로 돌아가 복제 전 상태를 복원하고 앞으로 가서 결과를 복원. 실제 삭제가 아닌 학습 상태 탐색임을 표시. 재생과 화면 요약 일치 및 포커스 복귀 확인.
9. 모바일·키보드·마감
   320/390/768/1440px에서 7개 기록을 각각 눌러 정확한 내용이 열림. 모든 기록 대상 ≥44×44, 겹침과 가로 넘침 없음.
   320×480의 긴 카드: 본문 scrollTop=0, 제목 top=35px, 확인 버튼 bottom=448px. 본문만 스크롤(client 344 / scroll 424px).
   Tab→확인, Enter→복귀, ESC→취소/확인, Home/방향키/End→탭 이동을 점검. 완료 포커스는 재시작 버튼이 아니라 결과 제목.
