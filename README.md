# GitHub 협업 실습실

`lab.html`에서 나와 **지수(가상 인물)**가 백설공주 이야기를 함께 씁니다. 기본 화면은 2D 협업 지도입니다. 위에는 GitHub 저장소, 아래에는 나와 지수의 독립된 로컬 저장소가 있습니다. 로그인이나 방 만들기 없이 혼자 진행합니다.

## 학습 흐름

- 나는 본문을, 지수는 제목을 고칩니다. 각자 수정 → 기록 → 공유하는 과정을 직접 진행합니다.
- 공유하면 같은 기록이 GitHub에도 생깁니다. 로컬의 기록은 사라지지 않으며, 공유만으로 GitHub 기준본이 바뀌지는 않습니다.
- 지수의 제목을 먼저 검토해 합친 뒤, 내 본문에 대한 지수의 의견을 읽고 보완 → 재기록 → 재공유 → 승인 → 병합을 경험합니다.
- 최종 기록에는 지수의 제목과 내 본문이 함께 들어갑니다. 합친 결과는 내 컴퓨터와 지수의 컴퓨터가 각각 받아와야 합니다.

두 초안은 모두 가능한 이야기입니다. 내용의 정답을 찾기보다, 변경이 어디에 있고 누가 볼 수 있는지에 집중합니다. 지수는 정해진 시나리오로 작업하고 검토하는 가상 인물이며 자연어를 판단하는 AI가 아닙니다. 실제 GitHub 저장소를 변경하지 않습니다.

## 탐색과 실험

**이전 단계 · 지나온 장면 선택 · 다시 앞으로**로 방문한 상태를 오갈 수 있습니다. 보기만 하면 선택·대화·승인이 보존됩니다. 과거에서 다른 선택을 적용하면 그 뒤의 기록과 검토를 다시 진행합니다. 아직 방문하지 않은 장면으로 건너뛸 수는 없습니다. 이 탐색은 교보재 상태를 되돌리는 기능이며 실제 Git 기록 삭제와는 다릅니다.

**다른 방법 실험하기**에서는 기준에서 바로 고치거나 공유 전후 지수가 GitHub에서 볼 수 있는 내용을 비교하고, 실험 이전 상태로 돌아올 수 있습니다. 기록을 누르면 당시 내용을 확인할 수 있습니다. 명령어와 세부 용어는 접힌 참고 영역에 있습니다.

**3D 기록 참고**는 별도의 10단계 3D 참고 화면입니다. 구슬 클릭, 회전, 확대, 배치 조정을 제공합니다. 기본 2D 실습에는 WebGL이 필요하지 않습니다.

## 실행

Node.js 20 이상에서:

```sh
npm start
```

`http://localhost:4173/lab.html`을 엽니다. 서버는 정적 파일만 제공하며 방, 참여자, 실시간 동기화 API가 없습니다. 실습 상태는 브라우저 메모리에 있고 새로고침하면 초기화됩니다.

정적 호스팅에도 `lab.html`, `lab.js`, `lab-model.mjs`, `mission-model.mjs`, `mission-ui.mjs`, `collaboration-map.mjs`, `lab.css`, `assets/`를 함께 올리면 동작합니다. JavaScript 모듈을 사용하므로 `file://` 직접 열기 대신 HTTP 서버를 사용하세요. 3D 참고 화면은 WebGL 2가 필요합니다. Three.js 0.180.0과 OrbitControls를 로컬에 포함해 실행 중 CDN 접속은 필요 없습니다. 라이선스: `assets/vendor/three/LICENSE` (MIT).

## 검증

```sh
npm test
```

독립된 로컬 기록, 공유 전후 가시 범위, 두 기여의 병합, 각각의 받아오기, 원본 직접 수정 실험, 이전·다음 상태 복원, 선택 변경 시 승인 초기화와 최신 기록 승인 조건을 검사합니다. 정적 서버의 파일 제공과 비공개 파일·폐기된 방 API 접근 차단도 검사합니다.

## 사용 방법

- 이전·다음: 화면 버튼, 좌우 방향키, PageUp·PageDown
- 첫 장·마지막 장: Home·End
- 발표자 노트: 화면 버튼 또는 N, 닫기: Esc
- 발표·세로 읽기 전환: 화면 버튼 또는 R
- 전체화면: 화면 버튼, 해제: Esc
- 인쇄: 화면 버튼 또는 브라우저 인쇄 메뉴
- 흑백: 흑백 버튼 선택 후 인쇄

좁은 화면이나 세로 화면은 읽기 모드로 시작합니다. 넓은 표는 표 영역을 가로로 스크롤해 확인할 수 있습니다. 모바일에서 인쇄하려면 브라우저 메뉴를 사용합니다. 인쇄 시 브라우저의 머리글·바닥글을 끄고, 색상 보존을 위해 배경 그래픽을 켭니다. 인쇄 페이지는 16:9 가로, 슬라이드당 한 페이지입니다.

## 시각 자료와 데모

- 2장: 같은 FAQ 파일의 수정 전·후 비교
- 4·8·12장: 실제 GitHub 공개 화면의 고해상도 확대 캡처
- 9장: 작업 브랜치 분기·commit·merge 데모
- 10장: 저장·staging·commit 데모
- 11장: Push 한 번의 실행 전·후 비교, main 유지 확인
- 15장: Pull 한 번의 실행 전·후 로컬 main 비교
- 21장: 30초 MP4 협업 흐름 영상, 무음·한국어 설명 자막

데모의 ‘재생’, ‘다음 단계’, ‘처음’ 버튼으로 조작합니다. 슬라이드를 넘기면 영상과 데모 재생이 멈춥니다. 인쇄에서는 영상 포스터와 데모의 정지 화면을 표시합니다. 좁은 화면의 도식은 영역 안에서 가로 스크롤할 수 있습니다.

실제 화면은 GitHub 공개 저장소 [github/docs](https://github.com/github/docs)와 [PR #45779](https://github.com/github/docs/pull/45779), [변경 비교](https://github.com/github/docs/pull/45779/files)에서 2026-09-08에 캡처한 발췌입니다. 해당 PR은 교육용 FAQ 예시와 별개의 실제 사례입니다. 당시 화면을 그대로 사용하며 이름·상태·코드의 합성 변경은 없습니다.

`demo.js`의 조작형 도식과 `assets/demo/workflow-captioned.mp4`는 이 자료를 위해 제작한 교육용 시뮬레이션입니다. 실제 GitHub 조작을 녹화한 영상과 구분합니다. 각 점은 기록된 버전을 뜻하며 라임색 점은 FAQ 변경의 기록입니다. 상세 개념은 발표자 노트와 원고를 참고합니다.

추가 파일: `demo.css`, `demo.js`, `assets/screens/`, `assets/demo/`. 영상에는 한글 설명이 화면에 포함되어 있으며 별도 자막 파일 `workflow.ko.vtt`도 제공합니다.

Push·Pull 비교 화면은 별도 작업 단계를 나열하지 않고, 한 명령을 실행하기 전과 실행한 후의 상태를 표시합니다. ‘Push 실행 보기’·‘Pull 실행 보기’는 슬라이드 안의 시뮬레이션 버튼으로, 실제 저장소를 변경하지 않습니다.

21장 영상의 6개 단계에 한국어 설명 자막을 직접 포함했습니다. CC 설정이나 별도 자막 파일 로딩 없이 표시됩니다. `assets/demo/workflow-captioned.mp4`를 단독 재생해도 자막이 보이며, 편집용 `workflow.ko.vtt`도 동봉합니다.

## GitHub Pages 배포

`main` 브랜치의 저장소 루트에서 배포합니다. `.nojekyll`로 정적 HTML·CSS·JavaScript와 미디어 파일을 그대로 게시합니다. `main`에 변경을 push하면 GitHub Pages가 사이트를 갱신합니다.
