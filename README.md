# GitHub 협업 실습실

`lab.html`에서 나와 지수(가상 인물)가 백설공주 이야기를 수정합니다. **나는 PR을 작성하고, 지수는 검토·병합과 로컬 충돌 해결**을 맡습니다. 종합 실습에는 민수도 참여하며, 민수의 PR은 병합 없이 닫힙니다. 실제 프로젝트에서는 여러 사람이 검토와 병합을 나눠 맡을 수 있습니다.

## 세 실습 탭

- **협업 기초**: 내 저장소 복제 → 브랜치 → 파일 수정 → 기록 → 공유 → PR → 지수의 수정 의견 → 재수정 → 지수의 승인·병합 → 내 기준본 받아오기. PR 하나로 기본 흐름을 익힙니다.
- **이슈와 충돌**: 두 이슈를 내게 할당 → 두 작업 브랜치와 PR → 첫 PR 병합 → 지수가 로컬에 복제 → 남은 PR 브랜치에서 충돌 해결·기록 → Push → 재검토·병합 → 병합 결과 받아오기.
- **종합 실습**: 나·지수·민수가 같은 저장소에서 작업합니다. 내 PR의 수정 의견 반영과 충돌 해결을 이어가며, 민수의 PR은 범위에 맞지 않아 병합 없이 닫습니다. 세 PR의 서로 다른 검토 결과를 비교합니다.

세 탭은 진행 상태를 따로 보관합니다. 3D 참고 화면은 제거했습니다.

## 화면과 실제 상태

처음에는 GitHub 저장소에만 기록 B가 있습니다. 각자의 **저장소 복제하기**를 실행한 뒤에만 로컬 파일과 기록이 나타납니다. 협업 기초 탭은 내 로컬만 표시합니다. 이슈와 충돌·종합 실습 탭의 지수는 충돌 해결이 필요해졌을 때 최신 저장소를 복제합니다.

B, C, D 등은 파일명이 아니라 기록 이름입니다. 기록을 누르면 당시 `snow-white.md` 내용을 볼 수 있습니다. 브랜치는 기존 기록을 가리키는 이름이며 별도 폴더를 만들지 않습니다.

본문 수정과 지수 의견 반영은 각각 한 가지 문장으로 진행합니다. 문장을 고르는 선택지는 없습니다. 파일 수정 창에는 수정 전·저장할 문장과 **이 문장 저장하기** 버튼만 있습니다.

## 역할과 충돌

나는 story PR #31과 happy PR #32를 서로 다른 브랜치에서 작성합니다. 지수는 두 PR을 검토하고, 필요한 충돌을 내 happy 브랜치에서 해결합니다. 같은 저장소의 작업 브랜치를 함께 수정할 수 있는 권한이 있는 상황을 가정합니다.

이슈 할당은 담당자 배지가 이슈에 붙는 모습으로 표시합니다. 할당만으로 파일이나 브랜치는 생기지 않습니다. PR #31이 먼저 병합되면 기준본 M1과 PR #32의 H가 같은 줄에서 충돌합니다. 지수는 저장소를 복제한 뒤 로컬 happy 브랜치를 열고, main을 합쳐 봅니다. 두 문장을 비교해 파일을 저장한 뒤 별도로 해결 기록 R을 만듭니다.

R은 먼저 지수의 로컬에만 생깁니다. Push해야 같은 PR #32의 head가 H에서 R로 바뀝니다. 지수가 재검토·병합하면 main이 M2가 됩니다. 나와 지수는 각자의 main에서 병합 결과를 받아옵니다. 이슈는 PR의 `Closes #번호` 연결에 따라 병합 시 닫힙니다.

종합 실습 탭에서 민수는 자기 로컬의 proposal 브랜치에 신데렐라 장면 S를 기록하고 PR #33을 만듭니다. 지수는 백설공주 프로젝트의 범위를 벗어났다는 의견을 남기고 이 PR을 병합 없이 닫습니다. 수정 후 재검토하는 PR #31과 구분합니다. S와 proposal 브랜치는 남지만 main에는 들어가지 않습니다. 이슈 #23도 자동으로 닫히지 않습니다.

이 사례는 [로컬 충돌 해결](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/resolving-a-merge-conflict-using-the-command-line)과 [PR의 검토·병합·닫기](https://docs.github.com/en/pull-requests/reference/pull-requests)를 교육용으로 단순화했습니다. 웹 편집기에서도 단순한 충돌은 해결할 수 있으나, 이 실습은 로컬 작업과 공유의 차이를 보여 주기 위해 로컬 경로를 사용합니다.

## 변경 설명과 탐색

동작마다 복사·할당·병합을 **실제 지도 위에서** 보여 줍니다. 자동 설명 팝업은 없습니다. 변경 요약과 다음 행동 버튼은 화면 아래에 고정됩니다. **설명**을 누르면 전체 설명을 읽고, **다시 보기**를 누르면 같은 애니메이션을 재생합니다.

GitHub, 로컬, PR 상태, 다음 행동을 한 화면에 배치했습니다. 페이지 스크롤과 자동 화면 이동은 없습니다. 높이가 낮은 가로 화면에서는 GitHub와 로컬을 좌우로 놓습니다. 파일·기록·PR·이슈의 상세 내용은 눌렀을 때만 열립니다. 상세 창의 긴 내용은 창 안에서 읽을 수 있습니다. 애니메이션 뒤에는 다음 동작을 할 수 있습니다. 모션 감소 설정에서는 이동 없이 변경 위치를 표시합니다. 재시작은 선택입니다.

이전 단계와 다시 앞으로는 방문한 학습 상태를 복원합니다. 실제 Git 기록을 삭제하는 동작은 아닙니다. 이전 단계에서 새 동작을 하면 그 이후 진행 결과를 다시 만듭니다. 새로고침하면 모든 실습이 초기화됩니다.

## 실행

Node.js 20 이상에서:

```sh
npm start
```

`http://localhost:4173/lab.html`을 엽니다. 서버는 정적 파일만 제공합니다. 로그인, 방 만들기, 실시간 다중 접속은 없습니다. 실제 GitHub 저장소를 변경하지 않습니다.

미리보기를 사용하는 동안 서버를 실행해 두어야 합니다. 서버가 꺼졌다면 `npm start`로 다시 실행한 뒤 페이지를 새로고침합니다. HTML·CSS·스크립트는 캐시에 저장하지 않습니다. 페이지를 받은 뒤 스타일이나 모듈을 읽지 못하면 오류 안내와 **다시 불러오기** 버튼을 표시합니다.

정적 호스팅에는 `lab.html`, `lab.js`, `lab.css`, `workshop-model.mjs`, `workshop-ui.mjs`, `workshop-motion.mjs`와 서체·브랜드 이미지가 있는 `assets/`를 포함합니다. JavaScript 모듈 때문에 `file://` 대신 HTTP로 실행해야 합니다. WebGL이나 Three.js는 사용하지 않습니다.

## 사용 방법

- 이전·다음: 화면 버튼, 좌우 방향키, PageUp·PageDown
- 첫 장·마지막 장: Home·End
- 발표자 노트: 화면 버튼 또는 N, 닫기: Esc
- 발표·세로 읽기 전환: 화면 버튼 또는 R
- 전체화면: 화면 버튼, 해제: Esc
- 인쇄: 화면 버튼 또는 브라우저 인쇄 메뉴
- 흑백: 흑백 버튼 선택 후 인쇄

좁은 화면이나 세로 화면은 읽기 모드로 시작합니다. 넓은 표는 표 영역을 가로로 스크롤해 확인할 수 있습니다. 모바일에서 인쇄하려면 브라우저 메뉴를 사용합니다. 인쇄 시 브라우저의 머리글·바닥글을 끄고, 색상 보존을 위해 배경 그래픽을 켭니다. 인쇄 페이지는 16:9 가로, 슬라이드당 한 페이지입니다.

## 시각 자료와 데모

- 2장: 같은 FAQ 파일의 수정 전·후 비교
- 4·8·12장: 실제 GitHub 공개 화면의 고해상도 확대 캡처
- 9장: 작업 브랜치 분기·commit·merge 데모
- 10장: 저장·staging·commit 데모
- 11장: Push 한 번의 실행 전·후 비교, main 유지 확인
- 15장: Pull 한 번의 실행 전·후 로컬 main 비교
- 21장: 30초 MP4 협업 흐름 영상, 무음·한국어 설명 자막

데모의 ‘재생’, ‘다음 단계’, ‘처음’ 버튼으로 조작합니다. 슬라이드를 넘기면 영상과 데모 재생이 멈춥니다. 인쇄에서는 영상 포스터와 데모의 정지 화면을 표시합니다. 좁은 화면의 도식은 영역 안에서 가로 스크롤할 수 있습니다.

실제 화면은 GitHub 공개 저장소 [github/docs](https://github.com/github/docs)와 [PR #45779](https://github.com/github/docs/pull/45779), [변경 비교](https://github.com/github/docs/pull/45779/files)에서 2026-09-08에 캡처한 발췌입니다. 해당 PR은 교육용 FAQ 예시와 별개의 실제 사례입니다. 당시 화면을 그대로 사용하며 이름·상태·코드의 합성 변경은 없습니다.

`demo.js`의 조작형 도식과 `assets/demo/workflow-captioned.mp4`는 이 자료를 위해 제작한 교육용 시뮬레이션입니다. 실제 GitHub 조작을 녹화한 영상과 구분합니다. 각 점은 기록된 버전을 뜻하며 라임색 점은 FAQ 변경의 기록입니다. 상세 개념은 발표자 노트와 원고를 참고합니다.

추가 파일: `demo.css`, `demo.js`, `assets/screens/`, `assets/demo/`. 영상에는 한글 설명이 화면에 포함되어 있으며 별도 자막 파일 `workflow.ko.vtt`도 제공합니다.

Push·Pull 비교 화면은 별도 작업 단계를 나열하지 않고, 한 명령을 실행하기 전과 실행한 후의 상태를 표시합니다. ‘Push 실행 보기’·‘Pull 실행 보기’는 슬라이드 안의 시뮬레이션 버튼으로, 실제 저장소를 변경하지 않습니다.

21장 영상의 6개 단계에 한국어 설명 자막을 직접 포함했습니다. CC 설정이나 별도 자막 파일 로딩 없이 표시됩니다. `assets/demo/workflow-captioned.mp4`를 단독 재생해도 자막이 보이며, 편집용 `workflow.ko.vtt`도 동봉합니다.

## GitHub Pages 배포

`main` 브랜치의 저장소 루트에서 배포합니다. `.nojekyll`로 정적 HTML·CSS·JavaScript와 미디어 파일을 그대로 게시합니다. `main`에 변경을 push하면 GitHub Pages가 사이트를 갱신합니다.
