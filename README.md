# GitHub 온보딩 HTML 슬라이드

## 각자의 로컬을 보여주는 협업 지도

`lab.html`의 기본 화면은 **2D 협업 지도**입니다. 위에는 GitHub 원격 저장소, 아래에는 나와 동료의 독립 로컬 저장소가 있습니다. 원근·카메라 조작 없이 각 저장소의 기준과 작업 기록을 나란히 비교합니다. 기존 슬라이드의 **협업 실습** 링크로 이동합니다.

나는 백설공주의 본문을, 동료는 제목을 수정합니다. 각자 로컬에서 기록을 만든 뒤 GitHub로 공유하며, 공유만으로 팀 기준이나 다른 사람의 로컬이 바뀌지는 않습니다. 동료 제목의 반영 P와 내 본문 D를 병합한 M에는 두 수정이 모두 들어갑니다. 이후 나와 동료가 각각 받아와야 각자의 로컬 기준도 갱신됩니다.

첫 본문 선택 두 개는 모두 자연스러운 문장입니다. 선택에 맞춰 동료가 이어 쓸 장면을 제안합니다. 수정·검토 내용은 필요한 때만 창으로 펼치고, 기록 버튼을 눌러 각 시점의 내용을 확인할 수 있습니다. **3D 기록 참고**는 별도의 보조 화면으로 남겨두었습니다. 2D 미션 자체는 WebGL이 필요 없습니다.

**다른 방법도 실험해보기**에서는 기준에서 직접 수정하거나 공유 전후 GitHub에서 보이는 내용을 비교하고, 실험 전 상태로 돌아갈 수 있습니다.

### 이전 장면으로 돌아가기

장면 위의 **이전 단계**, **지나온 장면 선택**, **다시 앞으로**로 방문한 상태를 탐색할 수 있습니다. 모달에서도 이전 단계로 돌아갈 수 있습니다. 탐색만 하면 선택·대화·승인 결과가 보존되며, 실제 Git 기록을 삭제하는 동작이 아닙니다. 과거에서 다시 조작하거나 선택을 적용하면 그 지점 뒤의 경로를 버리고 기록·리뷰·승인을 새로 진행합니다. 아직 방문하지 않은 단계로 건너뛰거나, 바뀐 내용에 예전 승인을 재사용할 수 없습니다.

함께 접속한 경우 작성자가 공유 장면을 이동하며, 카메라는 각자 유지합니다. 역할은 과거 상태로 되돌아가지 않습니다. 실험 중에는 먼저 **실험 되돌리기**로 복귀한 뒤 장면을 이동합니다.

Google Stitch MCP에 비식별 화면 요약과 탐색 요구를 보내 디자인 검토를 받았습니다. 소스 코드나 스크린샷 검토는 아닙니다. 작은 탐색 컨트롤, 이후 경로 재진행 안내, 공유 장면/개인 시점 구분을 채택했습니다. CLI 패널과 새 브랜드 제안은 채택하지 않았습니다. 원문과 판단은 `design/stitch-review.txt`에 있습니다.

혼자일 때는 **지수 · 가상 동료**가 정해진 시나리오로 리뷰합니다. 자유로운 자연어 판단을 하는 AI 리뷰가 아닙니다. 함께 연습에서는 실제 참여자가 수정 요청과 승인을 보냅니다. 이 미션은 최신 수정에 대한 동료 승인을 병합 조건으로 정한 교육용 사례이며, 실제 GitHub의 필수 리뷰 설정은 저장소마다 다릅니다.

기존 Repo → Clone → Branch → Edit → Stage → Commit → Push → PR → Merge → Pull의 10단계는 **기록 흐름 참고**에서 탐색합니다. 이 참고 화면의 자유 배치 드래그는 개념 동작과 구분합니다. 참고 화면을 열어도 진행 중인 미션은 보존됩니다. HEAD·staging·base/compare·fast-forward와 명령어는 접힌 세부 설명에 있습니다. 이 예시는 충돌이 없는 merge commit과 fast-forward pull을 사용합니다. A/B/C/D/M/X 및 해시는 교육용 표기입니다.

### 실행과 여러 기기 참여

Node.js 20 이상에서 추가 패키지 설치 없이 실행합니다.

```sh
npm start
```

서버가 출력하는 `http://localhost:4173/lab.html`을 엽니다. **함께 조작하기**에서 이름을 입력하고 방을 만든 뒤 참여 링크를 공유합니다. 다른 기기는 같은 네트워크에서 접속합니다. localhost에서 복사할 때에는 서버가 감지한 사설 네트워크 주소를 사용합니다. 여러 네트워크 어댑터가 있다면 참여 기기와 연결된 주소를 사용하고, 운영체제 방화벽이 Node.js의 수신 연결을 허용해야 합니다.

- 한 방 최대 12명. 방을 만들면 새 미션이 시작되고 첫 참여자가 **고치는 사람**이 됩니다. 다른 사람이 **확인하는 동료 · 맡기**를 눌러 역할을 나눕니다. 나머지는 관찰할 수 있습니다. 직접 조작의 결과·실험·리뷰 대화·승인이 실시간으로 공유됩니다.
- 작성자는 수정·Commit·Push·병합을, 리뷰어는 수정 요청과 승인을 담당합니다. 작성자의 자기 승인, 승인 전 병합, ‘단계 이동’ API를 통한 미션 건너뛰기를 서버에서 거부합니다.
- 각자의 시점·선택한 커밋·퀴즈 응답은 독립적으로 유지됩니다.
- 서로 다른 구슬은 동시에 드래그할 수 있습니다. 같은 구슬은 잠깐 점유하며 놓거나 연결이 끊기면 해제됩니다.
- 동시에 진행 버튼을 누르면 한 번만 반영됩니다. 재연결 시 역할·대화·최신 미션 상태를 복구합니다. 연결이 끊긴 사람이 맡은 역할은 다른 적격 참여자가 이어받을 수 있습니다.
- 방 링크를 가진 사람이 참여할 수 있는 간단한 교육용 방입니다. 이름과 상태는 서버 메모리에만 있으며 재시작 시 사라집니다. 비어 있는 방은 2시간 후 정리됩니다.
- 서버는 기본적으로 `0.0.0.0:4173`에서 실행합니다. `HOST=127.0.0.1 npm start`로 내 컴퓨터에서만 열거나 `PORT=8080 npm start`로 포트를 바꿀 수 있습니다.

정적 GitHub Pages에는 `lab.html`, `lab.js`, `lab-model.mjs`, `mission-model.mjs`, `mission-ui.mjs`, `lab.css`, `assets/vendor/three/`를 함께 올리면 **혼자 미션·참고 탐색**이 동작합니다. 여러 기기 동시 조작에는 실행 중인 Node.js 서버가 필요합니다. 인터넷을 통한 참여는 HTTPS와 SSE 스트리밍을 지원하는 Node.js 호스트에 이 서버를 별도로 배포해야 합니다. GitHub Pages만으로 실시간 방을 운영할 수는 없습니다.

3D 모듈은 HTTP로 실행해야 하므로 `lab.html`을 `file://`로 직접 여는 방식은 지원하지 않습니다. Three.js 0.180.0과 OrbitControls를 로컬에 포함했으며 실행 시 CDN 연결은 필요 없습니다. WebGL 2를 지원하는 브라우저가 필요합니다. 라이선스: `assets/vendor/three/LICENSE` (MIT).

### 검증

```sh
npm test
```

이력과 브랜치의 일관성, 초안 C 보존과 보완 D 반영, 원본 직접 수정 실험의 로컬·원격 분리, 공유 전후 동료의 가시 범위, 실험 되돌리기를 검사합니다. 방문한 상태의 왕복 복원, 선택 변경 후 이후 승인 초기화, 미래 단계 건너뛰기 거부, 역할 유지도 검사합니다. 작성자·리뷰어 역할 제한, 최신 D 승인 조건, 승인 전 병합 거부, 중복 요청 거부, 실시간 상태 전달·방 격리와 비공개 파일 접근 차단도 검사합니다.

## 사용 방법

- 이전·다음: 화면 버튼, 좌우 방향키, PageUp·PageDown
- 첫 장·마지막 장: Home·End
- 발표자 노트: 화면 버튼 또는 N, 닫기: Esc
- 발표·세로 읽기 전환: 화면 버튼 또는 R
- 전체화면: 화면 버튼, 해제: Esc
- 인쇄: 화면 버튼 또는 브라우저 인쇄 메뉴
- 흑백: 흑백 버튼 선택 후 인쇄

좁은 화면이나 세로 화면은 읽기 모드로 시작합니다. 넓은 표는 표 영역을 가로로 스크롤해 확인할 수 있습니다. 모바일에서 인쇄하려면 브라우저 메뉴를 사용합니다. 인쇄 시 브라우저의 머리글·바닥글을 끄고, 색상 보존을 위해 배경 그래픽을 켭니다. 인쇄 페이지는 16:9 가로, 슬라이드당 한 페이지입니다.

## 시각 자료와 데모

- 2장: 같은 FAQ 파일의 수정 전·후 비교
- 4·8·12장: 실제 GitHub 공개 화면의 고해상도 확대 캡처
- 9장: 작업 브랜치 분기·commit·merge 데모
- 10장: 저장·staging·commit 데모
- 11장: Push 한 번의 실행 전·후 비교, main 유지 확인
- 15장: Pull 한 번의 실행 전·후 로컬 main 비교
- 21장: 30초 MP4 협업 흐름 영상, 무음·한국어 설명 자막

데모의 ‘재생’, ‘다음 단계’, ‘처음’ 버튼으로 조작합니다. 슬라이드를 넘기면 영상과 데모 재생이 멈춥니다. 인쇄에서는 영상 포스터와 데모의 정지 화면을 표시합니다. 좁은 화면의 도식은 영역 안에서 가로 스크롤할 수 있습니다.

실제 화면은 GitHub 공개 저장소 [github/docs](https://github.com/github/docs)와 [PR #45779](https://github.com/github/docs/pull/45779), [변경 비교](https://github.com/github/docs/pull/45779/files)에서 2026-09-08에 캡처한 발췌입니다. 해당 PR은 교육용 FAQ 예시와 별개의 실제 사례입니다. 당시 화면을 그대로 사용하며 이름·상태·코드의 합성 변경은 없습니다.

`demo.js`의 조작형 도식과 `assets/demo/workflow-captioned.mp4`는 이 자료를 위해 제작한 교육용 시뮬레이션입니다. 실제 GitHub 조작을 녹화한 영상과 구분합니다. 각 점은 기록된 버전을 뜻하며 라임색 점은 FAQ 변경의 기록입니다. 상세 개념은 발표자 노트와 원고를 참고합니다.

추가 파일: `demo.css`, `demo.js`, `assets/screens/`, `assets/demo/`. 영상에는 한글 설명이 화면에 포함되어 있으며 별도 자막 파일 `workflow.ko.vtt`도 제공합니다.

Push·Pull 비교 화면은 별도 작업 단계를 나열하지 않고, 한 명령을 실행하기 전과 실행한 후의 상태를 표시합니다. ‘Push 실행 보기’·‘Pull 실행 보기’는 슬라이드 안의 시뮬레이션 버튼으로, 실제 저장소를 변경하지 않습니다.

21장 영상의 6개 단계에 한국어 설명 자막을 직접 포함했습니다. CC 설정이나 별도 자막 파일 로딩 없이 표시됩니다. `assets/demo/workflow-captioned.mp4`를 단독 재생해도 자막이 보이며, 편집용 `workflow.ko.vtt`도 동봉합니다.

## GitHub Pages 배포

`main` 브랜치의 저장소 루트에서 배포합니다. `.nojekyll`로 정적 HTML·CSS·JavaScript와 미디어 파일을 그대로 게시합니다. `main`에 변경을 push하면 GitHub Pages가 사이트를 갱신합니다.
